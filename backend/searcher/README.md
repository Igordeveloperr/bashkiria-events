# Сервис поиска

FastAPI + SQLAlchemy 2 + psycopg, PostgreSQL 18. Сервис читает существующие
`parser_events` и `parser_event_sources`; схемой управляет Alembic из `backend/db`.
Миграция `0004_event_search` добавляет `pg_trgm`, GIN-индексы полного текста и
названия, индексы площадки, города и источников.

Из корня проекта:

```powershell
docker compose up -d --build searcher
```

Сервис ждёт готовую БД и успешные миграции. По умолчанию API доступен на
`http://localhost:8000`, Swagger — на `http://localhost:8000/docs`, OpenAPI —
на `/openapi.json`. Порт меняется через `SEARCHER_HTTP_PORT` в корневом `.env`.
Другие сервисы Compose обращаются к `http://searcher:8080`.

| Метод | Путь | OpenAPI operationId |
| --- | --- | --- |
| GET | `/events` | `search_events` |
| GET | `/events/{event_id}` | `get_event` |
| GET | `/venues/schedule` | `get_venue_schedule` |
| GET | `/events/{event_id}/similar` | `find_similar` |
| GET | `/health` | `health` |

Все аргументы, кроме UUID в пути, передаются query-параметрами. Имена операций
подходят для последующего подключения инструментов AI; этот сервис работает
самостоятельно, без вызовов модели. Подключение инструментов к чату — отдельный шаг.

## Полные события и пагинация

Каждое событие содержит все столбцы `parser_events`, включая
описание без обрезки, даты и время, цены, координаты, данные модерации и
`issues_json`, происхождение `source_type` и ссылки `city_id` / `venue_id` на справочники.
В `sources` возвращаются все столбцы связанных
`parser_event_sources`, включая ссылки, `raw_document_id`, `candidate_json` и
время проверки. Сырые HTML-страницы, история аудита и задания сбора не загружаются.
Дополнительное поле `time_zone` — `Asia/Yekaterinburg`.

`numeric` сериализуется в JSON строками, например `"price_min": "500.00"`,
чтобы сохранялась точность. UUID и даты — строки ISO 8601; отсутствующие
значения остаются `null`.

Все списковые операции возвращают:

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 50,
  "pages": 0,
  "has_next": false,
  "has_previous": false
}
```

`page` начинается с 1, `page_size` — от 1 до 500, по умолчанию 50.
Необязательный `offset` задаёт точное смещение от 0 и имеет приоритет над `page`;
это позволяет агенту запрашивать произвольные страницы без округления смещения. Запрос
страницы за концом списка возвращает пустой `items` с сохранением `total`.
Все сортировки дополнены UUID для устойчивого порядка. Подсчёт, страница и
источники читаются в одной транзакции `REPEATABLE READ, READ ONLY`. Между разными
HTTP-запросами данные могут измениться при новом сборе парсером.

## Поиск по фильтрам

Фильтры объединяются через AND; значения категорий и статусов внутри списка —
через OR. Списки передаются повторением параметра:
`?categories=Concert&categories=Theatre&tags=джаз&tags=дети`.

| Аргументы | Поведение |
| --- | --- |
| `q` | Русский полнотекстовый поиск по названию, описанию, городу, площадке, адресу и языку; также часть нормализованного названия и триграммная похожесть для опечаток |
| `title` | Часть исходного названия; `%` и `_` трактуются буквально |
| `categories` | `Other`, `Concert`, `Theatre`, `Exhibition`, `Festival`, `Cinema`, `Excursion`, `Workshop`, `Lecture` |
| `tags`, `tags_mode` | Метки; `all` по умолчанию, либо `any`. Регистр и `ё/е` не учитываются |
| `city` | Точное название города без учёта регистра и `ё/е` |
| `venue`, `address`, `language` | Часть соответствующего поля без учёта регистра и `ё/е` |
| `statuses` | Без параметра — все статусы (`Draft`, `Published`, `Cancelled`); переданные значения ограничивают выдачу |
| `public_only` | При `true` — только `Published` без ручного скрытия; по умолчанию `false` |
| `source_statuses` | `Unknown`, `Scheduled`, `Cancelled`, `Postponed`, `Rescheduled`, `SoldOut` |
| `date_from`, `date_to` | Пересечение с периодом `[date_from, date_to)`. Можно задать одну границу; datetime с обязательным UTC offset |
| `start_date_from`, `start_date_to` | Диапазон местных календарных дат **начала**, обе границы включены |
| `price_from`, `price_to` | Пересечение диапазона цен события с указанным бюджетом в рублях |
| `is_free` | Точный признак бесплатного входа |
| `age_limit_max` | Максимальное допустимое возрастное ограничение, 0–18 |
| `duration_from`, `duration_to` | Диапазон длительности в минутах, включительно |
| `source_id` | Точный идентификатор хотя бы одного источника без учёта регистра |
| `confidence_min` | Минимальная уверенность извлечения, 0–1 |
| `updated_since`, `verified_since` | Обновлено / проверено не раньше указанного datetime с UTC offset |
| `latitude`, `longitude`, `radius_km` | Все три аргумента вместе; расстояние по сфере, без PostGIS |
| `sort` | По умолчанию `relevance` при наличии `q`, иначе `date_asc`; явно доступны `date_asc`, `date_desc`, `price_asc`, `price_desc`, `updated_desc`, `relevance` (требует `q`) |
| `page`, `page_size` | Пагинация |

Поиск без фильтров возвращает все события, включая черновики и отменённые.
Для поиска только опубликованных передай `statuses=Published`.
Поиск без периода включает прошлые события. Неизвестные цена, возраст,
длительность и координаты не удовлетворяют соответствующим числовым фильтрам.
Для бесплатного события цена считается нулевой даже при пустых ценовых полях.
При единственной известной границе цены используется это значение.

В текстовом поиске совпадения в названии стоят выше упоминаний в описании.
«Новый год», «Нового года» и «новогодний» находят как праздничную фразу,
так и соответствующее прилагательное с учётом словоформ. Отдельные слова
«новые» и «год» в разных частях описания не считаются этой праздничной фразой.
Явная сортировка, например `sort=date_asc`, имеет приоритет над автоматической.

Пример с корректным кодированием кириллицы и знака `+` в UTC offset:

```python
import httpx

response = httpx.get("http://localhost:8000/events", params={
    "q": "джаз",
    "city": "Уфа",
    "categories": ["Concert", "Festival"],
    "date_from": "2035-01-10T00:00:00+05:00",
    "date_to": "2035-01-17T00:00:00+05:00",
    "price_to": 1500,
    "age_limit_max": 12,
    "sort": "relevance",
    "page_size": 100,
})
response.raise_for_status()
events = response.json()
```

## Расписание площадки

`get_venue_schedule` требует `venue`, `date_from`, `date_to`. Название площадки
сравнивается **точно**, без учёта регистра и `ё/е`. Дополнительные `city` и
`address` различают одноимённые площадки. Возвращаются опубликованные события
в хронологическом порядке с обычной пагинацией. Ответ дополнен `venue`,
`date_from`, `date_to`, `time_zone`.

```python
schedule = httpx.get("http://localhost:8000/venues/schedule", params={
    "venue": "ГКЗ Башкортостан",
    "city": "Уфа",
    "date_from": "2035-01-10T10:00:00+05:00",
    "date_to": "2035-01-10T23:00:00+05:00",
    "page_size": 100,
}).raise_for_status().json()
```

Интервал полуоткрытый: событие, завершившееся ровно в `date_from`, не попадает
в ответ, начавшееся ровно в `date_to` — тоже. Событие, начавшееся раньше периода
и продолжающееся внутри, попадает. Многодневные события также учитываются.
Если точного окончания нет, используется длительность. Если известна дата
окончания без времени — учитывается весь этот день. Событие без времени начала
занимает известный календарный день для отбора. Событие с известным началом
без окончания и длительности отбирается по моменту начала. Это правила отбора:
оригинальные `null` в ответе сохраняются, неизвестное время не выдумывается.

## Похожие события

Обязателен только UUID референса в `/events/{event_id}/similar`. Ответ содержит
`reference_event_id`, полные события и дополнительный `score` от 0 до 1 у каждого.

Оценка: 35% триграммная похожесть нормализованного названия, 15% — описания,
25% — пересечение тегов относительно их объединения, 15% — категория,
5% — город, 5% — площадка в этом городе. Пустые признаки не увеличивают оценку;
`Other` не считается совпадением категории. Одного общего города или площадки
недостаточно для попадания в кандидаты. Это детерминированное ранжирование по
содержимому, без эмбеддингов и внешней модели.

Параметры запроса — `min_score`, пагинация `page`, `page_size` / `offset`,
а также необязательные `city`, `date_from`, `date_to` и `public_only`.
Город сравнивается точно без учёта регистра; период — пересечение с полуоткрытым
диапазоном времени, как в поиске. Фильтры применяются до ограничения выдачи.
`public_only=true` исключает черновики, отменённые публикации и вручную скрытые записи.
`min_score` — минимальная оценка от 0 до 1, по умолчанию `0.15`.
В выдачу попадают события с `score >= min_score`; `min_score=0` убирает порог.
Без дополнительных фильтров похожие события отбираются по содержимому среди всех записей: с любыми
статусами, городами и площадками, включая прошедшие события и записи без даты.
Сам референс исключается; референсом может быть любая существующая запись.
Сортировка всегда по убыванию `score`, затем по дате, времени и UUID.

## Локальный запуск и проверки

Нужен Python 3.11+. Создай `backend/searcher/.env` по `.env.example`, выставь
в `DATABASE_URL` внешний порт PostgreSQL из корневого `.env`.
Вместо URL поддерживаются `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`;
URL имеет приоритет. В Compose используются отдельные переменные PostgreSQL,
поэтому пароль со специальными символами не нужно кодировать в URL.

```powershell
cd backend/searcher
uv sync --frozen
uv run --frozen uvicorn searcher.main:app --reload --port 8000
```

```powershell
uv run --frozen pytest -q
uv run --frozen ruff check searcher tests
uv run --frozen ruff format --check searcher tests
```

Для интеграционных тестов выстави `TEST_DATABASE_URL` PostgreSQL в окружении.
Они создают случайную схему, применяют настоящие миграции и удаляют только
свою схему. Без переменной эти тесты пропускаются. Миграции требуют права
`CREATE` в базе для установки `pg_trgm`; расширение остаётся общим в `public`.

Некорректные параметры возвращают 422, отсутствующий UUID события — 404,
ошибка БД или таймаут SQL — 503. `/health` проверяет подключение к БД.
Пул и таймаут на запрос SQL настраиваются через `DATABASE_POOL_SIZE`,
`DATABASE_MAX_OVERFLOW`, `DATABASE_STATEMENT_TIMEOUT_MS` (10 секунд по умолчанию).
Синхронные обработчики FastAPI выполняют psycopg-запросы в пуле потоков.

Сервис предназначен для внутреннего backend: он возвращает также данные
модерации, а поиск без фильтра статуса включает черновики. В Compose порт опубликован
только на loopback. Авторизация внешних пользователей остаётся на вызывающем backend.
