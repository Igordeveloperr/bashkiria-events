# Инструменты ИИ

В [tools.py](tools.py) находятся шесть функций с `@tool` и список `TOOLS`.
Схемы аргументов строятся из сигнатур и docstring автоматически; модели данных и
результатов вынесены в [models.py](models.py). Контракты доступны через `GET /api/tools`.
Каждый контракт содержит имя, назначение, JSON Schema аргументов (`parameters`)
и результата (`returns`), флаг `implemented: true`.
Инструменты подключены к GigaChat через `bind_tools`. Граф выполняет вызовы,
передаёт JSON-результаты модели и продолжает до итогового ответа. Допускается
до шести раундов и восьми вызовов за раунд; превышение завершает запрос понятным сообщением.

Поиск, карточки, похожие события и расписание используют HTTP API `searcher`.
Они возвращают опубликованные события без ручного скрытия; полная карточка
черновика или скрытого события возвращается как `event: null`.
Подписки и обращения записываются через `interactionService`. Город подписки
разрешается по точному названию или алиасу справочника `parser`, без создания городов.
Операции не изменяют каталог событий напрямую.

| Инструмент | Назначение | Аргументы | Результат |
| --- | --- | --- | --- |
| `search_events` | Поиск по фильтрам | Необязательные `city`, `category`, `period`, `price`, `age`, `text`; `limit=10`, `offset=0` | `events: EventSummary[]`, `total: int`, `limit: int`, `offset: int` |
| `get_event` | Полная карточка | Обязательный `event_id: UUID` | `event: EventCard` или `null`, если не найдено |
| `find_similar` | Похожие события | Обязательный `event_id: UUID`; необязательные `city`, `period`; `limit=10` | `events: {event: EventSummary, score: number}[]`, по убыванию сходства; исходное событие исключается |
| `get_venue_schedule` | Расписание площадки | Обязательные `venue: string`, `period`; необязательный `city`; `limit=10`, `offset=0` | `venue`, `city`, `period`, `events: EventSummary[]`, `total`, `limit`, `offset`; события по времени начала |
| `subscribe` | Подписка на фильтр | Обязательные `city: string`, `period`; необязательный `category` | `subscription_id: UUID`, `status: "active"`, `city`, `category`, `period`, `created_at` |
| `save_feedback` | Обращение к организатору | Обязательные `event_id: UUID`, `text: string` | `feedback_id: UUID`, `event_id: UUID`, `status: "submitted"`, `created_at` |

`user_id`, `session_id` и `request_id` берутся из контекста запроса чата.
Модель не может передать их или настройки доступа в аргументах инструментов.
Для операций записи `user_id` должен соответствовать требованиям Interaction API:
1–128 символов ASCII из букв, цифр, `_`, `.`, `:`, `-`.

`subscribe` требует отдельного явного согласия в интерфейсе:
`subscription_consent: true` в `POST /api/chat`. По умолчанию значение `false`.
Текст сообщения и аргументы модели не заменяют согласие. После ошибки предыдущего
запроса интерфейс отправляет подтверждённый запрос с новым `request_id`.
В CLI согласие задаётся флагом `--subscription-consent` на время запуска.
Подписка создаётся для канала `web`; точный повтор фильтров возвращает ту же подписку.

`save_feedback` регистрирует вопрос модератору по поводу события. Текст должен
содержать 1–5000 символов после trim. Ключ идемпотентности вычисляется из пользователя,
диалога, UUID запроса, события и текста. Повтор одного вызова в том же запросе
не создаёт второе обращение. Доставка организатору отдельно не подтверждается.

Адреса сервисов и ключи описаны в [README](README.md#подключение-инструментов).
HTTP-таймаут — `TOOL_HTTP_TIMEOUT_SECONDS` (10 секунд по умолчанию). Ошибки сервисов
и валидации возвращаются модели как JSON `{"error":{"code":"...","message":"..."}}`;
внутренние ответы, адреса подключения и ключи в них не включаются.

## Общие типы

| Тип | Формат и смысл |
| --- | --- |
| `period` | `{ "start": "2026-11-14", "end": "2026-11-30" }`; даты включительно, по местному времени события, `end >= start` |
| `price` | `{ "min": 0, "max": 1500 }`; границы в целых рублях, любая может отсутствовать или быть `null`; `max >= min`; `max: 0` — бесплатно |
| `category` | `concert` — концерт, `theatre` — спектакль, `exhibition` — выставка, `festival` — фестиваль, `cinema` — кино, `excursion` — экскурсия, `workshop` — мастер-класс, `lecture` — лекция, `other` — другое |
| `age` | Возраст посетителя, целое от 0 до 120; допускаются события с возрастным ограничением не выше этого возраста |
| `limit`, `offset` | Размер страницы от 1 до 100, смещение от 0; `total` — все совпадения до пагинации |
| `score` | Число от 0 до 1, больше — ближе к исходному событию |
| Временные метки | ISO 8601 с часовым поясом, например `2026-11-14T19:00:00+05:00` |

Все строковые аргументы должны содержать непробельный символ. Неизвестные поля
аргументов запрещены. Отсутствие необязательного поискового фильтра или `null`
означает отсутствие ограничения. Пустая выдача — `events: []`.

`EventSummary` содержит `id`, `title`, `category`, `tags`, `date_start`, `date_end`,
`city`, `venue`, `price_min`, `price_max`, `is_free`, `age_limit`.
`date_start`, `date_end`, `price_min`, `price_max`, `is_free`, `age_limit` могут быть `null`;
неизвестная цена не равна нулю. `age_limit` — `0`, `6`, `12`, `16`, `18` либо `null`.
Цены результатов сохраняют копейки и сериализуются десятичными строками, например `"500.50"`.
Отдельно доступны `start_date`, `start_time`, `end_date`, `end_time`, `time_zone`
и `source_status`. Если известно только число, время остаётся неизвестным.

`EventCard` дополняет краткую карточку полями `description`, `address`, `lat`, `lon`,
`duration_min`, `language`, `org_link`, `source_url`, `verified_at`, `status`.
Координаты, длительность, язык, ссылка на организатора, публичный источник и время проверки могут быть
`null`. `status`: `published`, `draft`, `cancelled`.

`submitted` в результате `save_feedback` означает регистрацию обращения;
доставку организатору контракт отдельно не подтверждает.
